# Amazon monetisation

Production uses `com.amazon.device:amazon-appstore-sdk:3.0.9`; no Google billing. The one-time `ENTITLED` SKU is `wordbloom.premium`. The first four puzzles, daily play, hints/settings and device-dependent voice are free. Premium opens the other twenty puzzles and five environments, expanded completion/difficulty statistics and 4 earned hints per first puzzle completion instead of 3. Unavailable language packs and 300 levels are not advertised.

Distribution boundary: Amazon [ended its Appstore for non-Amazon Android devices on 20 August 2025](https://developer.amazon.com/apps-and-games/blogs/2025/02/upcoming-changes-to-amazon-appstore-for-android-devices-and-coins-program), while retaining Fire tablet support. This Amazon build's purchase integration therefore targets supported Fire devices. The APK has responsive Android phone/tablet gameplay, but a separate distribution/billing decision is needed for premium sales outside Amazon devices. No Google billing was added to this Amazon build. Store unavailability leaves touch/text free play intact.

Normal-build prices come only from Amazon product data. £3.99 is a proposed console test price, not a hardcoded live price. Buying is disabled if product data is absent. Purchases are never simulated by production code. The explicit test double is in the debug source set. It is selected only with `-PdevBilling=true`, which also changes the application ID to `.dev` and displays a development banner and TEST ONLY price/message. Its private entitlement storage is isolated. Release always uses Amazon and excludes the test class. Five JVM contract tests cover test-mode labelling, purchase, failure, restore and revocation; they do not prove live Amazon behaviour.

The listener is registered before SDK requests. Resume retrieves user/product data and receipt updates. A success receipt must match SKU/type. Cancellation revokes access. Restore resets the cursor, consumes all pages, and selects the newest relevant receipt because lists can be unordered. Cache entries are bound to Amazon user ID. Offline failures retain saved access; a confirmed account change selects its own entitlement. A successful full restore with no receipt revokes that account's cached access. Fulfilment follows local persistence.

The Amazon SDK callback is the device trust boundary. No independent server Receipt Verification Service is implemented. Review that offline-first choice against owner security requirements. Private storage is not tamper-proof on compromised devices. SDK release configuration and real purchase, pending, cancellation, pagination, account-switch and restoration scenarios still require App Tester and live testing.

Create the app/entitlement in Amazon Developer Console, set marketplace prices, and supply app-specific SDK identity/public-key configuration required by Amazon's current setup. Console credentials and identities are not invented in this repository.

Sources reviewed 16 October 2026: [SDK integration](https://developer.amazon.com/docs/appstore-sdk/integrate-appstore-sdk.html), [IAP implementation](https://developer.amazon.com/docs/in-app-purchasing/iap-implement-iap.html), [App Tester setup](https://developer.amazon.com/docs/in-app-purchasing/iap-get-started.html).
